# Process 3 - Kontrolafgift (fine) dispute

Owner: **Razvan**. The passenger disputes a fine: complaint to Movia, Movia's decision (accept, reject or reduce), appeal to Ankenævnet, case handling, the board's decision and Movia's response. P3 is the group's DCR process and its knowledge-intensive process. It is linked to P2 (fine collection in Camunda), which pauses and resumes around it.


## What is where

| Folder | Contents |
|---|---|
| `models/as-is/` | AS-IS DCR model: `P3_asis_processdoctor.xml` (Process DoCtoR) and `P3_asis_dcrgraphs.xml` (dcrgraphs.net, with guards and the 30-day deadline) |
| `models/to-be/` | TO-BE DCR model in both formats: delay notice (P3-35) and system steps (fee payment, case creation) |
| `compliance/rules-as-is/` | Compliance rules R1-R8 as DCR graphs |
| `compliance/rules-to-be/` | R1-R9 for the TO-BE (R9: the board decides or the parties are told within 90 days) |
| `compliance/results/` | Screenshots of the conformance checks in Process DoCtoR |
| `logs/` | Event logs for conformance checking (see below) |
| `service/` | The P3 Flask app (`p3_app.py`), a demo event sender and the test-case runner |
| `cep/` | The P3 Siddhi app (`P3_Siddhi.siddhi`) |
| `docs/` | The TO-BE write-up and the pipeline setup guide (PDF) |

Each model must also be in source.zip as a PDF: add `P3_asis.pdf` and `P3_TOBE.pdf` (printed from Process DoCtoR) to the model folders.

## Logs

| File | What it is |
|---|---|
| `P3_execution_log.xes` | 22 test cases executed on the TO-BE graph on dcrgraphs.net through its API (`service/p3_run_cases.py`). Real executions; the dates are pretend dates so the 30- and 90-day rules can be checked |
| `P3_TOBE_mock_log_SYNTHETIC.xes` | **Synthetic.** 36 made-up cases for the TO-BE. D01-D08 and D10 each break one rule on purpose (R1-R8, R9), D09 breaks only the full model |
| `P3_mock_log_v2_SYNTHETIC.xes` | **Synthetic.** The same for the AS-IS (34 cases, R1-R8) |

Process DoCtoR's log generator does not support guards, time constraints or data, so the logs were generated by script. Results: every executed case fits the TO-BE model and R1-R9; in the synthetic logs each rule flags exactly its planted case.

## Running it

Setup and the full test run are in `docs/P3_pipeline_setup_and_test.pdf`. In short:

1. Siddhi in Docker: `docker run -d --name siddhi -p 9390:9390 -p 8090:8090 -p 8280:8280 siddhiio/siddhi-tooling:latest`, open `http://localhost:9390/editor`, paste `cep/P3_Siddhi.siddhi`, press Run once.
2. The Flask app (Command Prompt, in `service/`):
   ```
   pip install -r requirements.txt
   set CEP_URL=http://localhost:8280/p3
   python p3_app.py --graph <TO-BE graph id> --model ..\models\to-be\P3_TOBE_dcrgraphs.xml
   ```
   It asks for the dcrgraphs.net login at start; no credentials are stored in any file.
3. Send events to `http://localhost:8280/p3`, e.g. `{"event": {"fineId": "F201", "eventType": "FineIssued"}}`, and click decisions on `http://localhost:5000`.

Without dcrgraphs.net: `python p3_app.py --local --model ..\models\to-be\P3_TOBE_dcrgraphs.xml`.

## Interface (for P2 and the CEP)

- **In:** `POST http://localhost:8280/p3` with `{"event": {"fineId": ..., "eventType": ..., <data>}}`. Event types: `FineIssued`, `ComplaintReceived` (`onBehalfOfAdult`), `IdentityMisuseReported`, `ReminderSent`, `TransferredToGaeldsstyrelsen`, `AppealSubmitted` (`amount`), `FeePaid` (`amountDkk`). Names are placeholders until agreed with P2.
- **Out to P2** (Siddhi stream `ToP2`, logged until P2 runs in Camunda): fine cancelled, new deadline (with the new amount), appeal case created (pause collection).
- **Shared key:** the fine number.
